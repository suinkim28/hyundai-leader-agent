# 본부장 AI 비서 — 에이전트 스켈레톤

본부장 1:1 AX Session 산출물. **본부장 한 분당 하나씩 복사해서 쓰는 초기
구조**다. 이 폴더를 통째로 본부장 PC에 두고 이름만 바꾸면 그 순간부터 동작한다.

작성 2026-09-01, 갱신 2026-09-03 · 엘리스 김수인 CRO
레포 `elice/ax/projects/hyundai-leader-agent`

> **2026-09-03 갱신** — 현대차 ICT 가 `HMG-LeaderAXSession-PILOT` 앱으로
> Microsoft Graph 위임 권한 19종을 승인했다. 자격증명 설정을 에이전트가
> 대신하도록 바꿨고(`.claude/commands/setup.md`), Graph 단일 진입점
> `bin/graph` 와 Files·Notes 조회를 추가했다. 자세한 것은 `SETUP.md` 하단.

---

## 무엇인가

빈 채팅창이 아니라 **운영 규칙과 하루 루틴이 이미 들어 있는 작업 폴더**다.
채팅창은 매번 처음부터 시작하지만 이것은 어제를 기억한다.

세 가지가 미리 들어 있다.

| | 들어 있는 것 | 파일 |
| --- | --- | --- |
| **규칙** | 출처 표기, 소스 우선순위, 확인 게이트, 기억 갱신 절차 | `SYSTEM.md` |
| **루틴** | 06:00 시장 브리핑부터 17:00 회고까지 8종 | `ROUTINES.md`, `.claude/commands/` |
| **안전장치** | 발송·변경·삭제 직전 재확인, 자격증명 보호, 출처 누락 감지 | `.claude/hooks/` |

비어 있는 것은 **본부장 개인 정보 하나**다. 그것을 채우는 절차가
`BOOTSTRAP.md` 에 있고, 첫 실행 때 에이전트가 스스로 시작한다.

---

## 첫 실행에 무슨 일이 일어나는가

본부장이 "오늘부터 비서 역할 좀 해줘" 라고 말하면, 일반적인 조언을 하지 않고
**질문하는 쪽이 된다.**

```
본부장:  오늘부터 비서 역할 좀 해줘.

에이전트: 시작하기 전에, 아직 본부장님에 대해 아는 것이 없습니다.
         12가지만 여쭙고 바로 한 가지를 실제로 해 보여드리겠습니다.
         20분 정도 걸립니다.

         먼저 — 직책과 담당 범위를 한 문장으로 말씀해 주시겠습니까?

본부장:  (답변)

에이전트: 기록했습니다. PROFILE.md → 직책·담당범위
         다음 — 하루 중 가장 시간을 많이 쓰시는 일 세 가지는 무엇입니까?
```

`PROFILE.md` 의 `상태: 미완료` 를 세션 시작 훅이 감지해서 부트스트랩으로
보낸다. 규칙은 안 읽힐 수 있지만 훅은 반드시 실행된다.

12문항이 끝나면 **그 자리에서 Quick Win 한 건을 실제 데이터로 돌려서
보여준다.** 설명하지 않고 돌린다. 결과를 보고 본부장이 "이건 이렇게 해달라"고
하시는 것 — 그것이 진짜 개인화이고, 그 지시가 `PROFILE.md` 에 쌓인다.

## 하루 루틴

| 시각 | 루틴 | 산출물 |
| --- | --- | --- |
| 06:00 | 시장·기술 동향을 3건 이내로 | `briefings/..._시장브리핑.md` |
| 08:00 | 일정 · 미결 결정 · 회신 필요 · 지연 과제를 한 장으로 | `briefings/..._아침브리핑.md` |
| 회의 전 | 자료를 읽고 **쟁점과 물으실 질문** 정리 | `briefings/..._회의준비.md` |
| 수시 | 개인·조직 맥락 반영 자료, 답변 초안 | `drafts/` |
| 결재 시 | 보고자료 요약 + 근거 부족·상충 표시 | `briefings/..._결재검토.md` |
| 회의 중 | 과제 기획·지연·리스크·담당자 추적 | `ORG.md`, `projects/` |
| 회의 후 | 녹음 전사 원문 → 요약 → 실행사항 | `meetings/transcripts/`, `meetings/logs/` |
| 17:00 | 회고 · 리더십 관찰 · **장기기억 갱신** | `briefings/..._회고.md` + 프로파일 |

06:00 / 08:00 / 17:00 은 무인 실행할 수 있다 (`scripts/run_routine.sh|ps1`).
무인 실행 중에는 확인이 필요한 행동을 시도하지 않는다.

## 세 가지 공통 원칙

### 1. 개인화 — 매일 자란다

세션에서 만든 것이 아니라 **매일 조금씩 자라는 구조**가 남아야 한다.

- 본부장이 답을 고치실 때마다 → `PROFILE.md` §4 답변 규칙에 한 줄
- 처음 나온 인물·용어 → `ORG.md`
- 내려진 결정과 근거 → `decisions/`

17:00 회고가 이 갱신을 매일 강제한다. **사흘 연속 갱신이 없으면 본부장께
알린다** — 안 쓰이고 있거나 학습 포착이 고장 난 것이다.

### 2. 출처 — 모든 사실에 붙인다

본부장은 이 답변을 그대로 들고 회의에 들어간다. "어디서 나온 얘기냐"에 답할
수 없으면 그날로 신뢰를 잃는다. 그래서 세 가지를 항상 구분한다.

| `[출처: 메일 2026-09-01 김OO]` | 자료에서 확인한 사실 |
| --- | --- |
| `[판단]` | 자료에 없는 나의 해석 |
| `[미확보 — 이유]` | 확인하지 못한 것 |

`cite_sources.py` 훅이 자료를 읽고 답한 턴에 출처가 하나도 없으면 지적하고,
`grounding_check.py` 가 자료에 없는 수치를 짚어낸다.

### 3. 훅 — 규칙을 기계가 강제한다

| 훅 | 하는 일 |
| --- | --- |
| `session_start.py` | 개인화가 비어 있으면 부트스트랩으로 보낸다 |
| `guard_external_actions.py` | 발송·변경·삭제 직전에 대상과 내용을 보여주고 되묻는다 |
| `protect_secrets.py` | 자격증명 파일 덮어쓰기를 막는다 |
| `cite_sources.py` / `grounding_check.py` | 출처 누락과 근거 없는 수치를 알린다 |

**조회는 전부 통과시키고 바깥세상을 바꾸는 것만 잡는다.** 모든 것을
확인받게 하면 이틀 만에 꺼버린다. 본부장별 차이는 `.claude/gate_policy.json`
등급으로 조정한다 (`SECURITY.md` §2).

## 연결이 없어도 동작한다

승인은 늦게 나온다. 그래서 이 스켈레톤은 **연결이 하나도 없어도 성립하도록**
설계했다. 연결은 기능을 늘리는 것이지 동작의 전제가 아니다.

| 상태 | 되는 것 |
| --- | --- |
| 완전 오프라인 | 회의록 · 회고 · 의사결정 이력 · 과제 추적 · 문서 검토 |
| + 로컬 파일 (내보낸 메일·일정) | 위 + 메일 트리아지, 일정 브리핑, 보고자료 검토 |
| + Confluence / Jira | 위 + 사내 지식 검색, 과제 자동 추적 |
| + Microsoft Graph | 위 + 아침 브리핑 자동화, 회의 준비 자동 트리거 |
| + STT | 위 + 회의 녹음 → 회의록 자동 생성 |
| + 외부 웹 | 위 + 시장 동향, 법규·경쟁사 조사 |

**1회차 세션은 첫 줄만으로도 성립하도록 준비한다.** 승인을 기다리다가 세션
당일에 아무것도 못 보여주는 것이 최악이다.

지금 무엇이 되고 무엇이 안 되는지:

```bash
python3 scripts/check_connections.py
```

각 항목에 "막히면 무엇을 잃는가"와 "대신 무엇을 할 수 있는가"가 함께 나온다.

## 파일 구성

```text
├── SYSTEM.md          운영 규칙 (에이전트가 읽는 정본)
├── PROFILE.md         본부장 개인 프로파일     ← 비어 있음. 부트스트랩이 채운다
├── ORG.md             본부 조직·과제           ← 챔피언이 초안 작성
├── ROUTINES.md        루틴 8종 명세
├── BOOTSTRAP.md       개인화 4단계 절차
├── CONNECTIONS.md     연결 설정과 대체 경로
├── SECURITY.md        확인 게이트 정책
├── SETUP.md           설치·사전 준비 (챔피언용)
├── HARNESS.md         실행 환경 검증과 대응 (H Code Desktop)
├── .claude/
│   ├── settings.json      권한과 훅 등록
│   ├── gate_policy.json   본부장별 확인 등급
│   ├── hooks/             안전장치 5종 + 실행 흔적 기록
│   └── commands/          슬래시 명령 10종
├── scripts/           조회·발송·전사·진단 도구
├── templates/         산출물 서식 5종
└── briefings/ meetings/ decisions/ projects/ drafts/ knowledge_base/ logs/
```

**파일명이 곧 인덱스다.** `YYYY-MM-DD_<제목>_<종류>.md` 규칙을 지키므로 별도
목록 파일을 두지 않는다. 목록은 반드시 낡고, 낡은 목록은 "거기 없는 것"이
실제로 없는 것인지 기록을 안 한 것인지 구분할 수 없어 없느니만 못하다.

## 이 설계가 답하고 있는 것

세션 전 OT에서 챔피언들이 말한 우려가 그대로 설계 요구사항이 됐다.

| 나온 말 | 이 스켈레톤의 대응 |
| --- | --- |
| "일회성으로 끝나는 게 아닐까. 주기적 업데이트가 핵심인데" | 17:00 회고가 매일 기억을 갱신하고, 사흘 비면 경고한다 (`BOOTSTRAP.md` 2단계) |
| "본부장님이 AI로 모든 걸 할 수 있다고 생각하시는 것 같다" | `PROFILE.md` §6 "다루지 않기로 한 것" 을 초반에 합의하고 기록한다 |
| "왜 굳이 에이전트를 만들어야 하는지 와닿지 않을 것 같다" | 12문항 뒤 **즉시** Quick Win 을 실제 데이터로 돌려 보여준다 |
| 지속 운영 가능한 형태여야 한다 | 규칙은 마크다운, 도구는 파이썬으로 분리. 하네스를 바꿔도 그대로 옮겨진다 |
| 임원에게 VS Code 는 낯설다 | H Code Desktop 위에서 돈다. 대신 훅이 실제로 사는지 `/selftest` 로 검증한다 |
| 승인이 늦어질 수 있다 | 연결 0개로도 동작. 승인마다 기능이 더해지는 구조 |

## 다음 본부장에게 복사할 때

`SYSTEM.md`, `ROUTINES.md`, `BOOTSTRAP.md`, `SECURITY.md`, `CONNECTIONS.md`,
`HARNESS.md`, `scripts/`, `templates/`, `.claude/` 는 **그대로** 간다.

`PROFILE.md`, `ORG.md`, `.claude/gate_policy.json` 과 작업 폴더는 비운 상태로
간다. 특정 본부장에게만 해당하는 것은 반드시 이 세 곳에만 있어야 한다.
`SYSTEM.md` 에 개인 사정이 섞여 들어가면 다음 사람에게 복사할 수 없게 된다.
