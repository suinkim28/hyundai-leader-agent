# 본부장 AI 비서 에이전트 스켈레톤

현대자동차그룹 본부장 1:1 AX Session 산출물입니다. **본부장 한 분당 하나씩
복사해 사용하는 초기 구조**이며, 이 폴더를 본부장 PC에 그대로 두면 즉시
동작합니다.

작성: 엘리스그룹 CRO 김수인

---

## 개요

빈 채팅창이 아니라 **운영 규칙과 하루 루틴이 이미 구성된 작업 폴더**입니다.
채팅창은 매번 처음부터 시작하지만, 이 구조는 어제를 기억합니다.

세 가지가 사전에 구성되어 있습니다.

| 구분 | 내용 | 파일 |
| --- | --- | --- |
| **규칙** | 출처 표기, 소스 우선순위, 되돌릴 수 없는 행동의 확인 원칙, 기억 갱신 절차 | `SYSTEM.md` |
| **루틴** | 06:00 시장 브리핑부터 17:00 회고까지 8종 | `ROUTINES.md`, `.claude/commands/` |
| **안전장치** | 자격증명 보호, 기억이 이 폴더 밖으로 새는 것 차단 | `.claude/hooks/` |

비어 있는 것은 **본부장 개인 정보 하나**입니다. 이를 채우는 절차는
`BOOTSTRAP.md`에 정의되어 있으며, 첫 실행 시 에이전트가 자동으로 시작합니다.

---

## 첫 실행

본부장께서 "오늘부터 비서 역할을 해달라"고 말씀하시면, 에이전트는 일반적인
조언을 제시하지 않고 **먼저 질문합니다.**

본부장께서는 이미 사전설문 14문항에 응답하셨고 60분 사전인터뷰도 진행하셨습니다.
같은 내용을 다시 여쭙지 않습니다. 에이전트는 먼저 워크스페이스에 사전자료가
있는지 확인하고, 없으면 다음 한 가지만 요청합니다.

```
본부장:   오늘부터 비서 역할을 좀 해주세요.

에이전트: 본부장님께 맞춰 드리려면 사전에 진행하신 인터뷰와 설문 내용이
          필요합니다. 그 내용을 이 창에 붙여넣어 주시거나 파일로 주시면
          제가 읽고 정리하겠습니다.

본부장:   (자료 제공)

에이전트: 사전자료에서 다음을 파악했습니다.
          시간을 가장 많이 쓰시는 업무는 보고서 검토와 회의 준비이고,
          정보는 주로 이메일과 Confluence에 있으며, 답변은 결론을 먼저
          제시하고 근거와 출처를 함께 붙이는 방식을 선호하십니다.
          확인 없이 진행하면 안 되는 것은 메일 발송과 문서 게시입니다.

          이 중 지금과 달라진 부분이 있으면 말씀해 주십시오.
```

`PROFILE.md`의 `상태: 미완료`를 세션 시작 훅이 감지해 부트스트랩으로 연결합니다.
규칙은 읽히지 않을 수 있으나 훅은 반드시 실행됩니다.

사전자료로 확인되지 않는 항목은 세 가지뿐이며, 이것만 추가로 여쭙습니다.
올해 본부의 최우선 목표, 직접 수행하시는 업무와 보고받아 판단하시는 업무의
비율, 브리핑을 받으실 시각과 경로입니다.

확인이 끝나면 **그 자리에서 Quick Win 한 건을 실제 데이터로 실행해
보여드립니다.** 설명하지 않고 결과를 제시합니다. 결과를 보시고 "이 부분은
이렇게 해달라"고 말씀하시는 내용이 실질적인 개인화이며, 그 지시가
`PROFILE.md`에 축적됩니다.

## 하루 루틴

| 시각 | 루틴 | 산출물 |
| --- | --- | --- |
| 06:00 | 시장 및 기술 동향을 3건 이내로 정리 | `briefings/..._시장브리핑.md` |
| 08:00 | 일정, 미결 의사결정, 회신 필요 사항, 지연 과제를 한 장으로 | `briefings/..._아침브리핑.md` |
| 회의 전 | 자료를 읽고 **쟁점과 확인하실 질문**을 정리 | `briefings/..._회의준비.md` |
| 수시 | 개인 및 조직 맥락을 반영한 자료와 답변 초안 작성 | `drafts/` |
| 결재 시 | 보고자료 요약과 근거 부족 및 상충 지점 표시 | `briefings/..._결재검토.md` |
| 회의 중 | 과제의 기획, 지연, 리스크, 담당자 추적 | `ORG.md`, `projects/` |
| 수시 | 본부장이 지시한 일회성 작업(분석, 정리, 비교표) | `projects/YYYY-MM-DD-<이름>/` |
| 회의 후 | 녹음 전사 원문 저장, 요약, 실행사항 도출 | `meetings/transcripts/`, `meetings/logs/` |
| 17:00 | 회고, 리더십 관찰, **장기기억 갱신** | `briefings/..._회고.md` |

06:00, 08:00, 17:00 루틴은 무인 실행이 가능합니다 (`scripts/run_routine.ps1`). 무인 실행 중에는 확인이 필요한
행동을 시도하지 않습니다.

## 공통 원칙 세 가지

### 1. 개인화는 매일 축적됩니다

세션에서 완성하는 것이 아니라 **매일 조금씩 성장하는 구조**를 남기는 것이
목적입니다.

- 본부장께서 답변을 수정하실 때마다 `PROFILE.md` 답변 규칙에 반영합니다
- 처음 등장하는 인물과 용어는 `ORG.md`에 기록합니다
- 내려진 결정과 그 근거는 `decisions/`에 남깁니다

17:00 회고가 이 갱신을 매일 강제합니다. **사흘 연속 갱신이 없으면 본부장께
보고합니다.** 사용되지 않고 있거나 학습 포착 기능에 문제가 있다는 신호이기
때문입니다.

### 2. 모든 사실에 출처를 표기합니다

본부장께서는 이 답변을 그대로 지참하고 회의에 들어가십니다. "근거가
무엇인가"라는 질문에 답할 수 없으면 신뢰를 잃습니다. 따라서 세 가지를 항상
구분합니다.

| 표기 | 의미 |
| --- | --- |
| `[출처: 메일 2026-09-01 김OO]` | 자료에서 확인한 사실 |
| `[판단]` | 자료에 없는 에이전트의 해석 |
| `[미확보, 사유]` | 확인하지 못한 사항 |


### 3. 규칙은 훅이 강제합니다

| 훅 | 역할 |
| --- | --- |
| `session_start.py` | 설정과 개인화가 미완료이면 해당 절차로 연결합니다 |
| `protect_secrets.py` | 자격증명이 파일에 기록되는 것을 차단합니다 |
| `keep_memory_portable.py` | 기억이 워크스페이스 밖이나 특정 도구 전용 저장소에 쌓이는 것을 차단합니다 |

메일과 Teams 발송, 캘린더 변경을 기계적으로 막는 장치는 없습니다. 에이전트가
발송 전 `--dry-run` 으로 내용을 보여드리고 확인을 받는 규칙으로 운영합니다.
확실히 막아야 하면 `SECURITY.md` §2 의 방법을 씁니다.

## 연결이 없어도 동작합니다

승인은 예정보다 늦어지는 경우가 많습니다. 따라서 이 스켈레톤은 **연결이 하나도
없는 상태에서도 성립하도록** 설계했습니다. 연결은 기능을 확장하는 수단이며
동작의 전제 조건이 아닙니다.

| 상태 | 가능한 기능 |
| --- | --- |
| 완전 오프라인 | 회의록, 회고, 의사결정 이력, 과제 추적, 문서 검토 |
| 로컬 파일 추가 | 위 항목 + 메일 트리아지, 일정 브리핑, 보고자료 검토 |
| Confluence 및 Jira 추가 | 위 항목 + 사내 지식 검색, 과제 자동 추적 |
| Microsoft Graph 추가 | 위 항목 + 아침 브리핑 자동화, 회의 준비 자동 실행 |
| STT 추가 | 위 항목 + 회의 녹음 기반 회의록 자동 생성 |
| 외부 웹 추가 | 위 항목 + 시장 동향, 법규 및 경쟁사 조사 |

**1회차 세션은 첫 행만으로도 성립하도록 준비합니다.** 승인을 기다리다 세션
당일에 아무것도 시연하지 못하는 상황을 방지하기 위한 설계입니다.

현재 가능한 기능과 불가능한 기능은 다음 명령으로 확인합니다.

```powershell
bin\graph.cmd check
```

각 항목마다 "연결되지 않으면 무엇을 잃는가"와 "대신 무엇이 가능한가"가 함께
표시됩니다.

## 파일 구성

```text
├── SYSTEM.md          운영 규칙 (에이전트가 읽는 정본)
├── PROFILE.md         본부장 개인 프로파일     ← 비어 있음. 부트스트랩이 채웁니다
├── ORG.md             본부 조직 및 과제        ← 챔피언이 초안을 작성합니다
├── ROUTINES.md        루틴 8종 명세
├── BOOTSTRAP.md       개인화 절차
├── CONNECTIONS.md     연결 설정과 대체 경로
├── SECURITY.md        확인 원칙과 자격증명 관리
├── SETUP.md           설치 및 사전 준비 (챔피언용)
├── HARNESS.md         실행 환경 검증과 대응
├── DEVELOPMENT.md     개발자용: 테스트 환경, 배포 전 확인, 변경 이력
├── bin/graph.cmd      Microsoft Graph 단일 진입점 (Windows). macOS 는 bin/graph
├── .claude/
│   ├── settings.json      권한과 훅 등록
│   ├── graph_scopes.txt   요청 스코프 (Entra 승인 목록과 일치해야 합니다)
│   ├── hooks/             안전장치 3종
│   └── commands/          슬래시 명령 11종
├── scripts/           조회, 발송, 전사, 진단 도구
├── templates/         산출물 서식 6종
└── briefings/ meetings/ decisions/ projects/ drafts/ knowledge_base/ logs/
```

**파일명이 곧 인덱스입니다.** `YYYY-MM-DD_<제목>_<종류>.md` 규칙을 따르므로
별도 목록 파일을 두지 않습니다. 목록은 반드시 낡으며, 낡은 목록은 "해당
항목이 없는 것"이 실제로 없는 것인지 기록하지 않은 것인지 구분할 수 없어
오히려 혼란을 유발합니다.
